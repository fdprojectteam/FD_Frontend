06 — Current State Gap Analysis (As-Is vs Product Vision)
Purpose of this Document

The Current State Analysis identified how Fixed Deposit booking is commonly implemented across banks and fintech platforms.

However, understanding the existing journey alone is not sufficient. To build a world-class technology product, we must evaluate how the current experience differs from the product vision we are trying to achieve.

The purpose of this document is to identify the gaps between today's booking experiences and the desired investment experience defined by the platform's product philosophy.

Rather than focusing on incremental improvements, this analysis highlights opportunities to fundamentally improve how users complete an FD investment through technology, intelligent guidance, and user-centric design.

Product Vision Reference

Before identifying gaps, we reaffirm the vision that every booking experience should support.

Help users complete a Fixed Deposit investment with confidence, clarity, minimal effort, and complete transparency while building long-term trust in the platform.

This vision becomes the benchmark against which every aspect of the current booking journey is evaluated.

Gap Analysis Framework

Each stage of the current booking journey is assessed across six product principles:

Product Principle	Evaluation Question
Convenience	Is the process effortless?
Transparency	Does the user understand what is happening?
Intelligent Assistance	Does the system actively help the user?
Trust	Does the experience build confidence?
Consistency	Is the interaction predictable?
Performance	Does the experience feel fast and responsive?
Gap Analysis
1. Convenience
Current State

Most booking experiences require users to manually enter information that is already known or previously verified.

Users frequently:

Re-enter personal information.
Repeat verification steps.
Navigate multiple forms.
Perform repetitive actions.
Gap

The experience depends heavily on user effort rather than system intelligence.

Product Opportunity

The platform should:

Reuse verified information.
Prefill available data.
Reduce manual entry.
Eliminate duplicate tasks.
Minimize unnecessary screens.
2. Transparency
Current State

Investment details, calculations, validations, and next steps are often distributed across different screens with limited explanation.

Users frequently ask:

Why is this required?
How was this value calculated?
What happens next?
Gap

The booking process communicates actions but rarely explains them.

Product Opportunity

The platform should clearly explain:

Why information is requested.
How calculations are derived.
What users are confirming.
What happens after submission.

Transparency should be continuous rather than limited to the final review screen.

3. Intelligent Assistance
Current State

Most booking experiences behave like digital forms.

They wait for users to make mistakes before responding.

Gap

The platform reacts instead of guiding.

Product Opportunity

The system should proactively:

Validate information as it is entered.
Recommend appropriate defaults.
Highlight missing information early.
Explain important investment decisions.
Prevent common mistakes before submission.
4. Trust
Current State

Trust is often communicated through branding rather than through the interaction itself.

During booking, users frequently experience uncertainty regarding:

Payment processing.
Submission status.
Investment confirmation.
Data security.
Gap

The experience does not consistently reinforce confidence during critical moments.

Product Opportunity

Trust should be strengthened through:

Clear progress indicators.
Transparent review experiences.
Reliable system feedback.
Immediate confirmation.
Professional visual design.
Consistent interaction patterns.
5. Consistency
Current State

Interaction patterns vary across screens.

Validation messages, layouts, navigation, and terminology often change throughout the booking process.

Gap

Users must continuously adapt instead of relying on familiar interactions.

Product Opportunity

Every step should maintain:

Consistent layouts.
Predictable navigation.
Uniform validation behavior.
Common terminology.
Reusable interaction patterns.

Consistency reduces learning effort and increases confidence.

6. Performance
Current State

Users often experience:

Slow page transitions.
Loading interruptions.
Blocking validation.
Delayed confirmation.
Gap

Technical implementation interrupts user momentum.

Product Opportunity

The Booking module should feel responsive through:

Progressive loading.
Immediate feedback.
Optimistic interactions where appropriate.
Background processing.
Efficient frontend rendering.

Performance contributes directly to perceived trust.

Summary Gap Matrix
Product Principle	Current State	Desired Future State
Convenience	Manual and repetitive workflows	Guided, low-effort experience with intelligent defaults
Transparency	Limited explanations	Continuous clarity and understandable financial information
Intelligent Assistance	Reactive validation	Proactive guidance and error prevention
Trust	Built mainly through branding	Reinforced through every interaction
Consistency	Varying patterns across screens	Unified interaction model throughout the journey
Performance	Interruptions and waiting	Fast, responsive, and predictable experience
Strategic Opportunities

The analysis identifies several opportunities that can differentiate the platform from traditional banking applications.

Transform Booking into Guidance

Instead of asking users to complete forms, guide them through an investment journey with contextual assistance.

Reduce Cognitive Load

Present only the information users need at the appropriate moment, avoiding unnecessary complexity.

Increase Transparency

Explain calculations, validations, and outcomes in clear, accessible language.

Build Confidence Continuously

Trust should be reinforced from the first step through to confirmation, not reserved for the end of the process.

Design for Reusability

Create modular capabilities—such as investment summaries, nominee management, and review components—that can support future investment products.

Design Implications
Product Decisions
Replace form-centric workflows with guided investment experiences.
Reduce manual effort through intelligent defaults and reusable user data.
Keep investment context visible throughout the booking process.
UX Decisions
Use progressive disclosure to manage complexity.
Provide contextual guidance instead of lengthy instructions.
Make review and confirmation feel like reassurance rather than administrative tasks.
Engineering Decisions
Build reusable booking capabilities rather than tightly coupled pages.
Implement real-time validation and state persistence.
Optimize rendering and data fetching to maintain a responsive experience.
Establish consistent component patterns for forms, summaries, and feedback.
Success Indicators

The redesigned Booking module should:

Require fewer user actions to complete an investment.
Reduce booking abandonment.
Increase first-attempt completion rates.
Lower support requests related to booking.
Improve user confidence at every stage of the journey.
Document Outcome

This Gap Analysis establishes why the current industry approach is insufficient and defines the strategic direction for a technology-first Booking experience. It bridges the gap between understanding the present and designing the future.

By documenting these gaps explicitly, every enhancement we introduce in the next phase will have a clear product rationale aligned with our vision of creating a trustworthy, intelligent, and globally competitive investment platform.
