# M2.7 — UI Fidelity Checklist

Project: FD Investment Platform
Date: 2026-07-31
Binding spec: `m2.7-implementation-plan.md` §8
Scope: what the Comparison screens must satisfy before M2.7 closes

Rows are grouped by the task that owns them. Rows marked **manual** cannot be
verified in jsdom and need a real browser.

---

## A. Structure and ordering (T2.7.3, T2.7.4)

| # | Requirement |
|---|---|
| A1 | Section order: back link → title row → column headers → table → Select row → action bar |
| A2 | Exactly one `h1`, and it is the "Comparing N of 4…" title |
| A3 | No skipped heading level |
| A4 | "‹ Back to Marketplace" is a `<Link>` to `ROUTES.home`, never `router.back()` |

## B. The table (T2.7.4)

| # | Requirement |
|---|---|
| B1 | A real `<table>` — not a grid of divs |
| B2 | Product headers are `<th scope="col">`; attribute labels are `<th scope="row">` |
| B3 | Row order: Interest Rate · Tenure · Minimum Investment · Interest Earned · Maturity Value · Benefits · Eligibility |
| B4 | Column order is the user's selection order, left to right |
| B5 | Each column header shows `BankBadge` + bank name + a remove control |
| B6 | Remove controls name their product ("Remove HDFC Bank from comparison") |
| B7 | One "Select" per column, below the table |

## C. Best-value highlighting (T2.7.1, T2.7.4)

| # | Requirement |
|---|---|
| C1 | Interest Rate — highest wins |
| C2 | Minimum Investment — **lowest** wins |
| C3 | Interest Earned — highest wins |
| C4 | Maturity Value — highest wins |
| C5 | **Tenure has no winner** — neither direction is universally better |
| C6 | Benefits and Eligibility have no winner |
| C7 | **A tie highlights the leftmost column only** — the approved screen shows HDFC and IDFC both at ₹10,000 with only HDFC marked |
| C8 | A winning cell uses `surface-brand-subtle` + brand text + trailing ★ |
| C9 | ★ and colour are **not** the only signal — each winning cell carries a visually-hidden qualifier |
| C10 | With one product, every scored row would trivially "win" — confirm whether highlighting is suppressed (assumption, see plan §8) |

## Verification note

Rows in group D and E3/E5 describe **layout and scroll behaviour**. The
verification harness has no layout engine and no scrolling, so it can confirm
the markup and the handlers exist but not that snapping, stickiness, or
overflow behave. Those are manual, exactly as M2.6's breakpoint rows were —
recorded here so a green suite is not mistaken for pixel verification.
