### What changed to get here

**A3.** `SearchBar` is now presentation-only:

```ts
export interface SearchBarProps {
  values: MarketplaceSearchValues;
  onSubmit: (values: MarketplaceSearchValues) => void;
}
```

It imports no hook, no router, no service. `MarketplaceSearchValues` moved to
`types/filters.ts` so the component does not reach into the hook layer even
for a type. `useMarketplaceSearchParams` lost its `commit` — it is now a
read-only selector, which makes I2a a property of the code rather than a
convention: the only route to a write is `useMarketplaceUrlState`, and
`HomeScreen` is its only caller.

**A4.** `ProductGridSection` takes `currentPage` from URL state.
`meta` now supplies only `total` and `totalPages`. `ResultCount` follows the
same split — position from the URL, totals from the response.

## 6. Production readiness verdict

**M2.4 is architecturally sound and functionally correct. It is not yet
shippable.**

- Every architectural invariant (I1–I6, including I2a) is enforced and
  verified by executable probes rather than by convention.
- Every behavioural claim in the M2.4 brief — pagination, sorting, URL
  updates, deep links, refresh persistence, back/forward, focus management,
  keyboard navigation — has been exercised against the real components and
  passes.
- The toolchain is clean: types, lint, formatting, boundaries, production
  build.

The single blocker is **C0**. It is not a design question and not a risk to
be accepted — the product's main screen is currently unreachable, and one
file deletion fixes it.

**Sign-off condition:** delete `src/app/page.tsx`, run `npm run build`, and
confirm `/` reports ~10.2 kB rather than 123 B. At that point M2.4 is closed.

## 7. Phase readiness

**M2.5 may begin once C0 is applied.** No architectural change to M2.4 is
required to support it:

- the URL writer already merges unknown parameters — verified with `bank` and
  `minRate`, which are M2.5's own;
- `ProductListParams` already carries `bank`, `tenureMonths`, `minRate`,
  `amount`, and `category`, and the MSW handlers already honour them;
- `marketplaceKeys.products.list(params)` already hashes deterministically
  over any parameter set;
- `HomeScreen` is the sole URL owner, so `setFilters` has exactly one place
  to live;
- every section component is presentation-only, so filter chips slot in as
  props without touching the data layer.

The M2.5 plan is in `docs/development/m2.5-implementation-plan.md`.
