# FD Platform — Global UX Audit

This audit was completed against the implemented public routes before the focused improvements in T3.2.11. The application already has explicit loading, empty, error and success states across the major journeys; this pass prioritises understanding, trust, conversion and responsive usability rather than recreating those foundations.

| Screen | Persona | Problem | Severity | Recommendation |
| --- | --- | --- | --- | --- |
| Home | Depositor, general user | The hero described a market-wide, live proposition ("most trusted", "50+", "available today") although the POC uses a static catalogue. | 🔴 Critical | State the decision benefit and label catalogue-driven figures as demonstrative. |
| Home | Investor, Gen Z | “Recommended for you” appeared before any preference was supplied. | 🟠 High | Frame it as exploration by need, reserving recommendation language for the goal planner. |
| Marketplace cards | Depositor, general user | The maturity figure was labelled “Estimated returns”, making it unclear whether it was interest or the total received; the investment amount was secondary. | 🔴 Critical | Present a clear “you invest” → “estimated at maturity” relationship, with the term beside it. |
| Product details | Experienced user | Terms, insurance and rating signals were available, but static POC data was not clearly distinguished from verified bank terms. | 🔴 Critical | Add a source/provenance disclosure adjacent to the decision information and direct customers to confirm final terms before booking. |
| Goal planner | General user, experienced user | The loading status claimed that deposit insurance was checked even though the engine records this as an unavailable rule. | 🟠 High | Describe only the rule-based matching and explanation work that actually runs. |
| Comparison | Depositor, investor | Strong amount-aware comparison and booking handoff already exist. | 🟢 Polish | Retain the current information hierarchy and applied-vs-draft clarity. |
| Booking overview and flow | Depositor | Stepper, review, error handling and booking disclosures are already cohesive. | 🟢 Polish | Preserve the current flow; verify it after shared copy changes. |
| Portfolio | Investor | Portfolio already communicates invested, contracted and maturity values accurately, with contextual maturity actions. | 🟢 Polish | Retain the existing “My Money” hierarchy and validate responsive cards. |
| Tax | General user, experienced user | Source and approximation labels are already clear and avoid implying a tax calculation. | 🟢 Polish | Retain the progressive disclosure and bank-document limitations. |
| Family | Investor | Demo family data is clearly labelled and separated from the investor’s own holdings. | 🟢 Polish | Preserve this limitation rather than inventing sharing capability. |
| Bank accounts and support | General user | Existing route-specific states and real support context are clear. | 🟢 Polish | Verify navigation and mobile layouts after shell changes. |
| Global navigation | Gen Z, mobile/tablet user | Eight desktop links appear from the tablet breakpoint, risking header crowding before there is enough horizontal space. | 🟠 High | Keep the compact menu and tab bar through tablet; switch to the complete desktop navigation only at the desktop breakpoint. |

## Focus selected for implementation

1. Make catalogue and calculation provenance explicit at the first decision points.
2. Make FD cards answer the investment → maturity question at a glance.
3. Keep recommendation language truthful and explain only rules the planner actually runs.
4. Protect the navigation and fixed mobile tab bar through tablet widths.
