### Two structural decisions taken during implementation

**The pure half of the URL layer was extracted.** `utils/url-values.ts` now owns
parsing, merging, and canonical serialisation; the hook keeps only what is
genuinely React's — subscribing to `useSearchParams` and being the single caller
of `router.replace()`. The reason is the same one that justified
`toProductListParams`: the URL contract is the part most likely to break
silently, and inside a hook it can only be checked by rendering something. It is
now asserted directly, 40 times.

**Filter controls are passed to `ProductGridSection` as a `toolbar` slot**
rather than as five filter props. The listing section renders a listing; it does
not need to understand facets, bank lists, or which filters are applied. This
mirrors how `SortControl` already arrives via `SectionHeading`'s `action`.

## 3. Defects found by the suite — all three fixed

### F1 — The tenure Select could not be cleared *(fixed)*

**Found by:** J5, "the panel follows the pill".

Removing the Tenure filter from a pill updated the URL, the chip row, and the
listing — but the search panel's Select still displayed "24 months". Radix
treats a `value` of `undefined` as *uncontrolled* and keeps the last selection,
and `SearchBar` passed `value={draft.tenure || undefined}`.

This is an M2.3 defect that could not surface until M2.5: with only one control
editing tenure, nothing ever cleared it from outside.

**Fix:** the Select is remounted when tenure goes from set to unset
(`key={draft.tenure ? 'tenure-set' : 'tenure-empty'}`). Switching between two
real tenures keeps the same key and stays controlled. The frozen `Select`
primitive is unchanged.

### F2 — I7 canonicalisation was only partial *(fixed)*

**Found by:** J6, rows 2 and 3 of the approved canonical table.

`merge()` deleted the keys named in the patch and left everything else alone, so
`?sort=interestRate&order=desc` and `?bank=` survived a user write. The approved
table says both must become `/`.

**Fix:** writes now serialise from *parsed values* instead of editing the
incoming query string. Three consequences beyond the fix itself:

- redundant defaults anywhere in the URL are dropped on any write, not only the
  key the user touched;
- parameter order is fixed, so one state has one URL down to the byte;
- no parameter outside the approved eight can survive a write — decision D2's
  closed set is now a property of the code rather than a convention.

---

### F3 — Back/forward could not restore filter combinations *(decided and fixed)*

**Found by:** J2.

Every Marketplace write used `router.replace()`, by the original rule 5.
`replace` overwrites the current history entry, so a session that searched and
then applied two filters produced **three writes and one history entry**.
Pressing Back did not undo a filter — it left the site, contradicting the M2.5
definition of done.

**Decision (approved):** `push` for user actions — search, filters, sort,
pagination, clear all. `replace` only for automatic corrections —
canonicalisation, normalisation of invalid values, and the out-of-range page
clamp. Recorded as **invariant I8** in `marketplace-url-state.md`.

**Implementation.** The single writer now takes a mode:

```
navigate(patch, mode)          the only navigation in the module
  ├─ commit(patch)   → router.push      intent
  └─ correct(patch)  → router.replace   correction
```

`setSearch`, `setFilters`, `clearFilters`, `setPage`, and `setSort` commit.
`correctPage` — used only by the out-of-range clamp — corrects. `HomeScreen`'s
clamp effect was moved from `setPage` to `correctPage`: pushing a correction
would let Back return to a URL already known to be broken, where the clamp would
simply fire again.

Rule 5 was amended from "one `router.replace()` per interaction" to "one
*navigation* per interaction". The count was always the point; I8 governs the
kind.

**Now verified (J2):** two refinements produce two pushes, zero replaces, and a
three-deep history stack. Walking backwards restores the URL, the search input,
the chips, and the result set at each step; walking forwards returns to the fully
refined state. No history navigation writes. The clamp (J3) replaces and adds no
entry.

**Note on M2.4.** The M2.4 report records "Back restores the previous state" as
passing. Under real `replace` semantics that state would not have been in the
history stack, so that assertion most likely reflected a harness whose stub
pushed. The behaviour it claimed was never shipped — until now.
