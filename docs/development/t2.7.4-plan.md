## 1. Decisions carried in from the T2.7.1 freeze review

Three were deferred with "decide at the start of T2.7.4, not inside it". They
are cheap now and expensive once two presentations exist.

### F1 — where the visually-hidden "best" qualifier is derived *(blocking)*

Checklist **C9** requires each winning cell to carry a hidden qualifier ("best
interest rate"), because ★ and colour cannot be the only signal (Document 14
§11). `CompareRow` carries `label` but no qualifier, and **both** the table
(T2.7.4) and the mobile card (T2.7.5) need one.

| | Approach | Assessment |
|---|---|---|
| **A** | A tiny exported helper beside the row spec — `bestQualifier(row)` → `Best ${label.toLowerCase()}` | One source, no type change, available to both presentations. `compare-rows.ts` already owns row vocabulary |
| **B** | A `bestLabel` field on `CompareRow` | Also one source, but changes a type frozen in T2.7.1 and adds a field only two components read |
| **C** | Each component composes its own string | Two copies of one sentence, drifting at the first copy edit |

**Recommendation: A.** C is what happens by default if we do not decide now.

### F2 — `rows` and `products` are parallel arrays *(blocking)*

`buildCompareRows` returns no product ids by design, so the header, remove
control and Select come from `products[j]` while values come from
`rows[i].values[j]` — two arrays, one index, soon two components. A filter or
reorder applied to one and not the other silently attaches HDFC's rate to
Kotak's column: wrong data that looks entirely right.

**Recommendation:** `CompareTable` takes **one** prop shape — `{ products, rows }`
— and never receives them from separate call sites, plus a journey assertion
that a named bank's column contains that bank's own rate. Cheap now; a
data-correctness defect later.

### F3 — the accessible reading of `—` *(blocking, small)*

A9 renders an em dash for a product with no benefits. Screen readers skip it or
announce "em dash"; neither says "no benefits". The model is right to stay
presentation-neutral, so this is a presentation decision: **show `—`, announce
"None"** via visually-hidden text. Same convention as F1's qualifier.

### F4 — confirm A8 in a browser *(not blocking)*

The catalogue cycles six rates across 18 generated products and repeats ₹10,000
nine times, so ties are routine, not edge cases. Two consequences to look at on
screen: the leftmost-tie rule decides the headline Interest Rate row often, and
**four products at one rate produce no star at all** on that row. That is A8
working; it should be seen before sign-off.

## 2. Scope gap found while planning

**The "Select" row has no owner.** The approved desktop screen shows one Select
button per column, below the table (§2.1 section 6). T2.7.4's deliverable names
the table, headers, highlighting and remove controls; T2.7.7 is the bottom
action bar ("Back to Marketplace" + "Proceed to Booking"). Neither names the
per-column Select.

**Recommendation:** it belongs to **T2.7.4**, because it is positioned per
column and its column identity comes from the same `products[j]` the header
uses — splitting it from the header is what makes F2's misalignment possible.
Inert per D3 (`aria-disabled`, no state carried).

Flagged rather than assumed: it is a task-boundary change, not a design change.

## 4. Verification impact

### 4.1 The journeys' DOM contract changes — re-point, do not weaken

L4/L6/L6b/L6c/L7 currently read `#compare-columns > li`. The table replaces that
markup, so `compareColumns()` and `compareNames()` must be re-pointed at
`<th scope="col">` cells.

This is the same discipline as the probe edits: **the helpers change, the
assertions do not.** A "fix" that relaxes an assertion to accommodate new markup
would quietly retire the behaviour L6b exists to protect.

### 4.2 New assertions

**Structure (A/B):** exactly one `<table>`; `<th scope="col">` per product and
`<th scope="row">` per attribute; row order matches `buildCompareRows`; column
order matches selection order; one remove control per column, each naming its
product; one Select per column.

**Highlighting (C):** the approved three-product fixture reproduces
`[1, null, 0, 2, 2, null, null]` in the DOM, not just in the model; a winning
cell carries brand surface **and** ★ **and** a hidden qualifier; Tenure carries
none.

**Alignment (F2):** a named bank's column contains that bank's own rate — the
assertion that catches a transposed index.

**Invariants:** `buildCompareRows` has **exactly one call site** (the probe
deferred from T2.7.1, now that a caller exists); `CompareTable` and
`CompareColumnHeader` are presentation-only (no store, no router, no service);
no component recomputes a financial figure; no new primitive under
`components/ui/`.

### 4.3 Known jsdom limits

Column overflow at four products, sticky behaviour, and any layout question stay
manual — the harness has no layout engine. Row and cell *semantics* are fully
testable and are what §4.2 asserts.
